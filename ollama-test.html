Testing Ollama

The AI chat in the app (c) talks to a local LLM through Ollama's HTTP API at http://localhost:11434. This page explains how that API works and lets you poke it directly from your browser.

Setup

Three steps before anything works.

Open this page over HTTP, not as a file

The interactive tests below use fetch() to call your local Ollama. If you open this page as file://... your browser sends Origin: null and Ollama answers 403 Forbidden. Serve it locally instead: 

bunx serve .          # or: python3 -m http.server

Then open http://localhost:3000/ollama-test.html. This also mirrors how the page behaves when published on GitHub Pages.

The three checks

  1. Install & run Ollama. Download from ollama.com, then start the server with ollama serve (or leave the desktop app running).
  2. Pull the model the app uses. ollama pull llama3.2 — the same value as AI_MODEL in the project's .env.
  3. Verify. The tests in the next section should all pass.

API Endpoints

Ollama exposes a plain HTTP API (no HTML UI). GET endpoints return server metadata; only the POST ones run the model — that's why they need a JSON body and return 405 Method Not Allowed if you hit them with GET in a browser tab.

MethodPathWhat it does
GET / Is the server up? Returns the plain text Ollama is running.
GET /api/version Server version, e.g. {"version":"0.32.9"}.
GET /api/tags List of downloaded models. Each model shows its size and capabilities (e.g. ["completion","tools"]).
POST /api/chat Runs the model with a conversation. Supports OpenAI-style tools (function calling). This is what the app uses.
POST /api/generate Runs the model with a single prompt (no chat history, no tools).

Same tests with curl

These work from any terminal and are the canonical way to check connectivity:

curl http://localhost:11434/                 # → Ollama is running
curl http://localhost:11434/api/version     # → {"version":"..."}
curl http://localhost:11434/api/tags        # → {"models":[...]}

The server only listens on localhost by default, so it's safe to hit it from a browser on the same machine.

Server Test

Three GET requests to confirm the server is up, report its version, and list the installed models. If "Models" shows llama3.2 with "tools" capability, the app's chat is ready to use.

Run the checks

GET /api/tags is the most useful: it proves the model you want is downloaded. If llama3.2 is missing, run ollama pull llama3.2.

Request & Response Fields

What each part of the body and the response means.

POST /api/chat — request body

FieldMeaning
modelWhich downloaded model to use. Must exist in /api/tags.
messagesThe conversation, an array of turns in order.
messages[].roleWho speaks: system (instructions), user, assistant, or tool (results of tool calls).
messages[].contentThe text of that turn.
toolsOptional. Function definitions the model may call (OpenAI-style). Omitted in a plain chat.
streamfalse → full answer at once. true → answer arrives token-by-token as a stream.

Response

FieldMeaning
message.contentThe model's answer — the only field the app uses.
message.tool_callsOnly present when you sent tools and the model decided to call one. Contains the function name and arguments.
donetrue when generation finished.
total_duration, eval_count, ...Performance metrics (nanoseconds, token counts). Safe to ignore.

Troubleshooting

Common issues and how to fix them.

ErrorCauseFix
405 Method Not Allowed Hitting /api/chat with GET in the browser. It's a POST-only endpoint. Use the chat tester above, curl, or Postman with method POST + JSON body.
403 Forbidden in the browser tests The page was opened as file:// (Origin: null). Serve the folder over HTTP: bunx serve . or python3 -m http.server.
Failed to fetch / connection refused Ollama isn't running, or the host/port is wrong. Run ollama serve and check the host field (default http://localhost:11434).
model 'llama3.2' not found The model isn't downloaded. Run ollama pull llama3.2 (or whatever AI_MODEL says).
First answer is slow The model is being loaded into RAM for the first time. Normal. Subsequent requests are faster. Bigger models need more RAM.
