About the Project

What is Expense Tracker AI and why it exists.

🎯

Purpose

Track personal expenses and automatically categorize them using AI. Get insights, spot trends, and make smarter financial decisions.

🤖

AI-First Development

Built using a multi-agent AI harness (.harness/) where specialized agents collaborate: an orchestrator plans, a developer codes, and a tester validates.

📐

Simple by Design

The project intentionally keeps its harness minimal. The goal is to understand how AI-agent architecture works in practice, without over-engineering.

Run It Live

Try the app in your own terminal. You only need Bun and a couple of commands.

Requirements

Bun >= 1.0. The TUI needs a real terminal (raw mode is not supported on piped stdin).

The AI chat (c) uses a local LLM via Ollama (default model llama3.2, run ollama pull llama3.2). Everything else works without it.

When adding an expense, the app suggests the matching group live as you type (instant local matching against group names and past expenses; press ? on the description to ask the AI when there's no local match).

Want to verify the connection from your browser? Open the Ollama test page — an interactive playground with curl examples, a chat tester, and a tool-calling demo.

Steps

git clone https://github.com/slaveofthecode/expense-tracker-ai.git
cd expense-tracker-ai
bun install
bun start

On first run, the app starts with an empty database. Everything you add, edit, or delete persists in .data/expenses.db (gitignored).

MCP Server

The app includes an MCP server that exposes expense analysis tools for any compatible client (opencode, Claude Desktop, Cursor, etc.).

Tools available: list_items, list_expenses, get_monthly_summary, get_yearly_summary, search_expenses, analyze_patterns, get_recommendations.

Agents

The main session plays the orchestrator role. developer, tester, and reviewer are registered as real subagents in all 4 tools (opencode, Claude Code, GitHub Copilot, Cursor) with isolated context and forced permissions — the reviewer is read-only.

Who/When: the main agent delegates to the matching subagent — developer codes, tester validates, reviewer checks quality.

orchestrator developer tester reviewer
🔧

Skills

Optional capabilities loaded on demand. The code-review skill checks for bugs, security issues, and bad practices.

Who/When: the agent performing the review, on request, whenever a code review is needed. Not run automatically on every task.

code-review
⚙️

Commands

Shortcuts for frequent tasks, invoked by the user and registered natively per tool. test validates types, code-style, and tests. pr generates a title/description, creates a GitHub PR, and returns to an updated main.

Who/When: test runs via the tester agent; pr via the orchestrator. Both run whenever the user invokes them.

test pr
🧠

Memory

Persistent storage for project decisions, user preferences, and session history. Conventions live under memory/conventions/.

Who/When: all agents read it at session start and update it as preferences are learned. code-style applies on every coding task; branch-naming when creating branches.

architecture code-style branch-naming
